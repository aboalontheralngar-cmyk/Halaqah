# Halaqah P1.27 Build 83 Hotfix 8

This build fixes three production blockers:

- Google OAuth now uses PKCE and `/auth/callback` instead of leaving access and
  refresh tokens in a `#access_token=...` URL.
- Cloud notification sync supports the current Flutter notification categories;
  `P1.27_BUILD83_HOTFIX8_APPLY.sql` expands the old cloud CHECK constraint and
  the app also contains a temporary legacy compatibility fallback.
- Upload-only synchronization uses a SQLite dirty-stage journal. The first
  Build 83 upload is intentionally full; later upload-only syncs skip domains
  that did not change, while a generation check prevents a concurrent local edit
  from being marked clean accidentally.

## Required cloud steps

1. Back up Supabase.
2. Run `P1.27_BUILD83_HOTFIX8_APPLY.sql`.
3. Run `P1.27_BUILD83_HOTFIX8_VERIFY.sql`; all rows must show `passed = true`.
4. In Supabase Auth -> URL Configuration set the production Site URL and add
   `https://YOUR_PUBLIC_APP_DOMAIN/auth/callback` to Redirect URLs.
5. Build the website with `NEXT_PUBLIC_APP_URL` set to the same public origin.
6. Configure/publish Google Auth Platform Branding. Do not share Client Secret
   JSON or OAuth refresh/access tokens.

## Flutter validation

```powershell
PowerShell -ExecutionPolicy Bypass -File .\tools\verify_source_prerequisites.ps1
flutter clean
flutter pub get
flutter analyze
flutter test
flutter run
```

The first device-to-cloud upload after installing Build 83 can take roughly the
same time as older builds because it establishes the dirty-stage baseline. A
second upload without edits should skip clean data domains and finish much more
quickly. Network/auth/connection checks still take non-zero time by design.
