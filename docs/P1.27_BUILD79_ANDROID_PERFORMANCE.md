# P1.27 Build 79 — Android Performance & Distribution Hardening

**Version:** `4.3.0-alpha.25+79`  
**Base:** Build 78  
**SQLite:** 26 (no schema change)  
**Supabase:** no new SQL  
**Goal:** reduce Android delivery size without changing the visual identity or removing production features.

## What was already optimized before Build 79

The Android release build already had:

- R8 code minification;
- `shrinkResources`;
- `proguard-android-optimize.txt`;
- a manual `tools/build_lean_android.*` script that could build split APKs.

Build 79 does not count those older measures as new savings.

## What Build 79 adds

### 1. Smaller per-device Android artifacts

The official release pipeline now builds:

- `app-arm64-v8a-release.apk` for most modern Android phones;
- `app-armeabi-v7a-release.apk` for older 32-bit ARM devices;
- `app-x86_64-release.apk` mainly for compatible x86_64 devices/emulators;
- `app-release.aab` for Google Play / bundle-based distribution.

The normal release path no longer depends on a universal-only APK.

### 2. Optimized resource shrinking for current AGP

`android/gradle.properties` enables:

```properties
android.r8.optimizedResourceShrinking=true
```

The project currently uses Android Gradle Plugin 8.7.3, where this activates the newer resource shrinking path while retaining the existing R8/minify configuration.

### 3. Unused direct dependency removal

Three direct dependencies had no imports/usages anywhere in `lib/` or `test/` and were removed:

- `cupertino_icons`;
- `image_picker`;
- `flutter_slidable`.

The accelerated crypto provider (`cryptography_flutter`) and production-critical plugins for Supabase, PDF/printing, QR scanning, secure storage, background work, contacts, permissions, and sharing remain intact.

### 4. Size regression reporting

`tools/android_release_size_report.dart` produces:

- `android-size-report.json`;
- `android-size-report.md`;
- `android-size-baseline-candidate.json`.

Once one real production release is accepted, its candidate can be committed as `tools/android_size_baseline.json`. Future CI builds can then detect unexpected size growth. Budget enforcement is opt-in with:

```text
HALAQAH_ENFORCE_SIZE_BUDGET=true
HALAQAH_MAX_SIZE_GROWTH_PERCENT=5
```

### 5. Lean release scripts now run quality gates

Both Windows and Bash scripts now run:

```text
flutter pub get
flutter analyze
flutter test
flutter build apk --release --split-per-abi
flutter build appbundle --release
```

They also archive obfuscation symbols, SHA-256 hashes, and the size report.

### 6. GitHub Android release pipeline

The GitHub workflow now:

- analyzes and tests before packaging;
- builds split APKs and AAB;
- verifies every APK signature;
- generates SHA-256 checksums;
- uploads a size report;
- optionally runs Flutter `--analyze-size` for ARM64.

## Why Quran JSON was not manually gzipped

`assets/quran_data.json` is about 2.77 MB uncompressed but highly compressible. APK/ZIP packaging already compresses JSON efficiently. Manually storing a gzip copy would shift decompression work to application startup for little or no meaningful download-size benefit, so Build 79 keeps the current fast startup path.

## Expected reduction

A percentage must be measured against a real **release** baseline, not a debug APK.

Expected safe ranges before the first measured Build 79 release:

- compared with a **universal release APK**: roughly **30–50% smaller per downloaded device APK** is a realistic target, driven mostly by ABI splitting;
- compared with the project's older **split-per-ABI lean script**: Build 79's additional gain is expected to be much smaller, roughly **3–12%**, because the largest split optimization already existed there;
- compared with a **debug APK**: no meaningful percentage should be reported because debug overhead makes the comparison misleading.

The exact percentage will be written into the generated size report after the first real release build.

## Build 78 compile regression closure

The owner's Flutter analyzer found eight Build 78 compilation issues after the SQL verification had passed. Build 79 fixes the source causes:

- decimal point totals now use `FutureBuilder<double>`;
- honor board scores preserve decimal values;
- Halaqah report imports `Helpers` correctly;
- legacy memorization reconciliation uses the existing `saveSetting` API;
- PDF aggregate values accept `num` and format decimal points;
- period report tests use `double` point arguments.

## Sync latency hardening

A slow `set_study_suspension` call must not block the full sync indefinitely. Build 79:

- bounds suspension cloud requests to 12 seconds;
- retains failed suspension deletions for the next retry;
- leaves local suspended dates intact for future automatic retry;
- skips only the temporarily unavailable suspension download section instead of failing every later sync section;
- replaces raw endpoint/exception text in the teacher UI with a safe offline-first message.


Send back `build/release-artifacts/android-size-report.md` so the exact reduction can be calculated and the first size baseline can be frozen.
