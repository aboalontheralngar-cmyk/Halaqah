# P1.27 Build 76 — SQL والإعداد

## نقطة البداية

قاعدة المالك اجتازت Build 75 VERIFY بالكامل. لذلك Build 76 **لا يعيد** Build 75 ولا P7.3، بل يطبق migration صغيرة إضافية فقط.

## 1. APPLY

نفّذ في Supabase SQL Editor:

```text
website/supabase/P1.27_BUILD76_APPLY.sql
```

المحتوى يطابق migration:

```text
website/supabase/migrations/20260814000100_build76_p127_completion.sql
```

### ما يضيفه

- تحديث `capture_sync_tombstone()` مع `mushaf_progress`؛
- trigger حذف لـ`mushaf_progress`؛
- `delete_student_for_sync(UUID)` كحذف ذري محمي بالنطاق؛
- `get_supervision_center_detail(UUID,UUID,DATE,DATE)` للـdrill-down؛
- تحديث `get_supervision_health()` إلى عقد `build76-2026-08-14`.

جميع دوال `SECURITY DEFINER` الجديدة تثبت:

```text
search_path = public, pg_temp
```

والـEXECUTE لا يُمنح لـanon.

## 2. VERIFY

بعد نجاح APPLY نفّذ:

```text
website/supabase/P1.27_BUILD76_VERIFY.sql
```

المطلوب أن تكون كل الصفوف:

```text
passed = true
```

الفحص يغطي:

- وجود RPCs الجديدة؛
- عقد health Build76؛
- grants للمستخدم authenticated؛
- trigger `mushaf_progress`؛
- `search_path` للدوال الحساسة؛
- بنية الاختبار الشهري المنظمة الموجودة من Build75.

## لا تشغّل

على قاعدة المالك الحالية لا تعاود:

- `P1.27_BUILD75_APPLY.sql`
- P7.3 القديمة
- `database_schema.sql`

إلا عند إنشاء بيئة جديدة بالكامل وفق runbook منفصل.

# P1.27 Build 78 — SQL والإعداد

قاعدة المالك يفترض أن تكون على Build76/77 قبل هذه الخطوة. Build78 migration **incremental** ولا تعيد P7.3 أو SQL الإصدارات السابقة.

## APPLY

نفّذ:

```text
website/supabase/P1.27_BUILD78_APPLY.sql
```

وهو مطابق byte-for-byte للمصدر:

```text
website/supabase/migrations/20260815000100_build78_reports_plans_supervisor_competitions.sql
```

يضيف/يعدل:

- `plans.friday_mode`؛
- `points.amount` إلى `NUMERIC(10,2)`؛
- `behavior_point_corrections.points_snapshot` إلى قيمة رقمية؛
- `supervisor_competitions`؛
- `supervisor_competition_categories`؛
- `supervisor_competition_entries`؛
- `supervisor_competition_scores`؛
- RLS للجهة والمراكز المرتبطة؛
- RPCs محمية للترشيح والسحب والتحكيم.

دوال `SECURITY DEFINER` الجديدة تثبت `search_path = public, pg_temp`، ولا تمنح الكتابة المباشرة إلى جداول المشاركات/الدرجات للمستخدم authenticated؛ الكتابة الحساسة تمر عبر RPC.

## VERIFY

بعد نجاح APPLY نفّذ:

```text
website/supabase/P1.27_BUILD78_VERIFY.sql
```

المطلوب أن تكون كل قيم `passed = true`. لا تعاود APPLY بسبب فشل واجهة الشبكة؛ احتفظ بنتيجة PostgreSQL الفعلية وافصل خطأ الاتصال عن خطأ SQL.
