# P1.26 Implementation Log — Typography, Contrast, Competition Maintenance, Safe Cloud Audit

**Release:** `4.3.0-alpha.19+73 (P1.26)`  
**SQLite:** `24` (unchanged)  
**Supabase:** guarded base bootstrap completed in the owner environment; post-bootstrap core completion is now prepared and separately verified.

## Why P1.26 exists

The owner reported two concrete acceptance failures after P1.25:

1. The Supabase preflight returned `STOP_BASE_SCOPE_MISSING` with all base-scope readiness flags false. This is a hard stop and means the P1.25 repair/verify must not be run yet.
2. Some Flutter screens had unreadable or inconsistent typography/contrast in both light and dark themes, and competitions could not be renamed or deleted.

## Completed source changes

### 1. Unified stable Arabic typography

- Flutter now uses the static `Tajawal` Regular/Bold assets as the application font family.
- PDF already uses the same static Tajawal files, so UI and exports no longer rely on two different shaping strategies.
- Explicit `Amiri` family references that were not declared as Flutter assets were removed/replaced by Tajawal, avoiding device-dependent fallback.
- The UI source no longer depends on the variable Readex Pro font for normal application text.

### 2. Light/dark contrast pass

- The global `TextTheme` applies `ColorScheme.onSurface` for body/display text.
- Chip and data-table text explicitly inherit scheme-aware foreground colors.
- Hard-coded low-contrast grey text/surfaces were replaced in the highest-traffic memorization, reports, students, settings, notifications, vacations, raffle, fund, home, and shared widget paths with `onSurfaceVariant`, `surfaceContainerLow/High`, `outlineVariant`, or equivalent scheme-aware values.
- Existing compact P1.23/P1.24 spacing and the restored green/gold identity remain unchanged.

### 3. Competition edit/delete

- Competition cards expose a menu for `تعديل الاسم والفئة` and `حذف المسابقة`.
- Editing preserves the event id/history and updates the mutable metadata.
- Deletion requires confirmation and deletes results + event in one SQLite transaction.
- Result counts are fetched through one grouped SQL query instead of one query per competition.

### 4. Supabase deep audit

Added `website/supabase/P1.26_SUPABASE_DEEP_AUDIT.sql`.

It is read-only and classifies the environment into one of these states:

- `EMPTY_PROJECT_READY_FOR_GUARDED_BASE_BOOTSTRAP`
- `STOP_ORPHAN_APP_TABLES_WITHOUT_BASE_SCOPE`
- `STOP_PARTIAL_BASE_SCOPE`
- `BASE_SCOPE_PRESENT_RERUN_P1_25_PREFLIGHT`
- `STOP_REVIEW_REQUIRED`

The P1.25 result `STOP_BASE_SCOPE_MISSING` is explicitly treated as **do not run the second migration and do not run the third verify**.

### 5. Guarded bootstrap for a truly empty application schema only

Added `website/supabase/P1.26_GUARDED_BASE_BOOTSTRAP.sql`.

- It may run only when the deep audit returns `EMPTY_PROJECT_READY_FOR_GUARDED_BASE_BOOTSTRAP`.
- Before any table creation it scans all known Halaqah application tables.
- If any such table exists it raises `P1.26_BOOTSTRAP_BLOCKED_EXISTING_APP_TABLES` and aborts the transaction.
- It creates only the base scope (`profiles`, `supervisors`, `centers`, `halaqat`, `center_members`, `families`, `family_guardians`) plus their safe scope helpers/RLS.
- It contains no `DROP TABLE`, `TRUNCATE`, bulk row deletion, or id conversion.
- After it succeeds, P1.25 preflight must be run again; the P1.25 repair remains gated by a `READY_...` result.

## Feature-status interpretation

The feature audit means “implemented in the current source tree,” not “accepted on every production integration.” Core workflows listed in `P1.25_REMAINING_FEATURE_AUDIT.md` exist in code. Items that depend on Supabase schema/RLS, Google provider configuration, Edge Functions, real printers/cameras, two-device conflict tests, or real backup restore remain acceptance/integration work until tested on the target environment.

## Validation added

`website/scripts/validate-p1-26-competition-contrast-bootstrap.mjs` protects:

- release identity/build number;
- Tajawal as the Flutter and PDF font;
- competition rename/delete and atomic deletion;
- absence of selected low-contrast patterns;
- read-only deep audit;
- guarded bootstrap and absence of destructive DDL/row rewrite;
- the existing P1.25 stop conditions.

Flutter/Dart SDK is not available in the editing environment, so `flutter analyze`, `flutter test`, and device visual acceptance still have to be run by the owner before promotion.

## Build 73 acceptance hotfix

The owner's real Flutter analyzer exposed seven remaining const-expression compile errors caused by `Theme.of(context)` inside `const Text` widgets. Build 73 removes only those invalid `const` qualifiers and adds a regression contract for the exact analyzer sites. The earlier build-72 import fixes remain.

The owner also supplied the post-bootstrap Supabase schema. It confirms the base Halaqah scope exists with UUID identifiers and that the Halaqah core/learning tables are still missing. `P1.26_POST_BOOTSTRAP_CORE.sql` is the current state-aware additive migration, and `P1.26_POST_BOOTSTRAP_VERIFY.sql` is the read-only acceptance check. Unrelated operational tables in the same public schema are explicitly outside the migration target.
