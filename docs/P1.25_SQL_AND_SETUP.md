# P1.25 — ترتيب Supabase الآمن بعد فشل P1.24

ظهور الخطأ:

```text
ERROR: 42P01: relation "public.students" does not exist
```

يعني أن قاعدة Supabase الحالية لا تطابق الافتراض الذي بُني عليه migration P1.24. **لا تعاود تشغيل P1.24 SQL ولا P1.24 verify على هذه القاعدة.**

## الخطوة 1 — فحص قراءة فقط

شغّل كامل محتوى:

```text
website/supabase/P1.25_SUPABASE_PREFLIGHT.sql
```

لا يغيّر هذا الملف أي بيانات أو بنية. راقب آخر نتيجة باسم `recommendation`.

### إذا كانت النتيجة تبدأ بـ STOP_

توقف. لا تشغّل migration الإصلاح. أرسل جميع نتائج preflight، لأن القاعدة تحتاج قرارًا خاصًا بمخطط المركز/الحلقة أو أنواع المفاتيح.

أمثلة:

- `STOP_BASE_SCOPE_MISSING`
- `STOP_BASE_SCOPE_COLUMNS_MISSING`
- `STOP_SCOPE_KEY_MISMATCH`
- `STOP_REFERENCE_TYPE_MISMATCH`

### إذا كانت النتيجة تبدأ بـ READY_

يمكن الانتقال للخطوة الثانية، مثل:

- `READY_FOR_P1_25_REPAIR`
- `READY_FOR_P1_25`

## الخطوة 2 — الإصلاح الإضافي

بعد نسخة احتياطية من Supabase، شغّل كامل محتوى:

```text
website/supabase/migrations/20260809000100_p1_25_cloud_compat.sql
```

هذا الملف مصمم ليكون إضافيًا: لا يحتوي `DROP TABLE` أو `TRUNCATE` أو حذف صفوف. إذا وجد تعارضًا في نطاق الصلاحيات أو نوع المفتاح يتوقف برسالة صريحة بدل تحويل المعرفات تلقائيًا.

## الخطوة 3 — تحقق قراءة فقط

فقط بعد نجاح الخطوة الثانية شغّل:

```text
website/supabase/P1.25_VERIFY.sql
```

أرسل النتيجة إذا ظهر:

- `missing_expected_columns > 0`
- `incompatible_uuid_columns > 0`
- أي `orphan_rows > 0`
- أي `duplicate_groups > 0`

لا نحذف orphan أو duplicate تلقائيًا؛ نحدد أولًا هل البيانات الأصلية موجودة محليًا أو في جدول آخر ثم نصلحها بأمان.
