# P1.27 Build 85 Hotfix 10

## Scope

This hotfix addresses two production issues reported after Build 84:

1. Bidirectional cloud sync can stop at the memorization/revision stage with `SYNC_MEMORIZATION_ARGUMENTERROR` when legacy cloud rows contain an ayah range that the local database validator rejects.
2. A newly authenticated Google/email user can receive a placeholder `profiles` row from the auth trigger and therefore be treated as fully onboarded before choosing a name, role, center, or supervisory organization.

## Memorization sync

Remote memorization rows are now rejected before local replay when `to_ayah` is greater than the selected surah's real ayah count. The batch replay also has a defensive row-by-row fallback for validation failures, so one malformed historical row is skipped and counted instead of aborting the entire sync stage.

No cloud memorization row is deleted by this hotfix.

## Website onboarding

`profiles.onboarding_completed` is the explicit account-readiness marker. New auth-created profiles default to `false`. The Build 85 SQL marks existing users as complete only when they already own or belong to a center/supervisory organization.

After OAuth/password authentication, the website resolves the profile before navigation:

- incomplete account -> `/onboarding`
- completed account -> `/select-center`

Google name metadata is used only as a suggested name in the onboarding form.

## Identity profile UI

The center selector and desktop dashboard sidebar display the signed-in user's name, email, and role. Dashboard logout now revokes the Supabase session instead of only clearing Zustand state.

## Database

Run `P1.27_BUILD85_HOTFIX10_APPLY.sql`, then `P1.27_BUILD85_HOTFIX10_VERIFY.sql` before deploying the Build 85 website.

Flutter local SQLite remains schema version 28.
