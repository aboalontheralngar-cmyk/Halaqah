# تسليم المرحلة P1.16 — السرد الرقمي وإصلاح إعداد الويب

الإصدار: `4.3.0-alpha.4+54 (P1.16)`  
التاريخ: 2026-07-22

## الناتج

- معالجة أخطاء VS Code المرفقة التي لا يجد فيها `react` و`next` وJSX بعد فك المصدر.
- أداة Windows موحدة لتثبيت حزم الويب المقفلة وفحصها وبناء الموقع.
- جلسة سرد/تلاوة رقمية منفصلة مرتبطة بالخطة ولا تزيد محفوظ الطالب.
- نطاق متصل قد يعبر السور وفق وحدة ومقدار الخطة.
- سجل للجلسات مع الجودة والملاحظات والحذف الكامل للجلسة.
- احتساب السرد محورًا ثالثًا في نسبة إنجاز الخطة.
- نطاقات قرآنية يومية فعلية للحفظ والمراجعة والسرد في الطباعة الفردية والجماعية.
- SQLite 20 ونسخ احتياطي ومزامنة Supabase رفعًا وتنزيلًا.
- RLS وفحص سحابي يمنع خلط الخطة والطالب والحلقة والتاريخ.

## حل المشكلة المرفقة على Windows

بعد استبدال المصدر الكامل افتح PowerShell من جذر `Halaqah` ونفذ:

```powershell
PowerShell -ExecutionPolicy Bypass -File .\tools\setup_web.ps1
```

بعد نجاحه افتح لوحة أوامر VS Code بـ`Ctrl+Shift+P` وشغّل:

```text
TypeScript: Restart TS Server
```

لا تُنسخ `node_modules` في ZIP؛ الأداة تعيد بناءها من `package-lock.json`.

## SQL المطلوب

1. خذ نسخة احتياطية.
2. نفّذ محتوى:

```text
website/supabase/migrations/20260722000400_p1_16_plan_recitation_tracking.sql
```

3. ثم نفّذ محتوى:

```text
website/supabase/verification/20260722000400_p1_16_plan_recitation_tracking_readiness.sql
```

المتوقع أربعة صفوف كلها `passed=true`. لا تنفذ اسم الملف نفسه.

## قبول سريع

1. افتح الخطط واضغط «تسجيل السرد وعرض الجلسات» لطالب لديه خطة نشطة.
2. اختر سورة وآية بداية، وتأكد من ظهور نطاق المقرر المقترح.
3. احفظ الجلسة وتحقق من ظهورها في السجل وارتفاع محور السرد في بطاقة الخطة.
4. احذف الجلسة وتأكد من انخفاض النسبة وبقاء محفوظ الطالب كما هو.
5. ارفع من جهاز، ثم نزّل على جهاز ثانٍ وتحقق من ظهور الجلسة نفسها.

## ما بقي بعد هذه الدفعة

- تكافؤ PDF الويب مع تقرير Android الإداري.
- تنزيل الصندوق والنقاط كاملًا وواجهة تسوية ويب مماثلة.
- توسيع البوابات والجهات الإشرافية وجولة التصميم النهائية.
