# P1.27 Build 82 Hotfix 7 — البوابة والمصادقة ومزامنة الحضور

التاريخ: 2026-08-17

## 1) SYNC_ATTENDANCE_23505

سبب الخطأ هو تعارض هوية سجل الحضور في السحابة. الهوية التجارية للحضور هي
`student_id + date`، بينما بعض السجلات القديمة قد تحمل UUID مختلفًا عن UUID
الذي كان Flutter يولده من الطالب/اليوم. إذا استُخدم المفتاح الأساسي `id` فقط
في upsert فقد يحاول Postgres إنشاء صف جديد ثم يصطدم بالفهرس الفريد
`uq_attendance_student_date` ويرجع 23505.

Build 82 يجعل Flutter يرفع الحضور باستخدام `onConflict: student_id,date` ولا
يرسل `id` في عملية upsert. بذلك يحتفظ الصف السحابي القديم بمعرفه ويُحدّث نفس
اليوم بدل محاولة إنشاء صف ثانٍ.

لا تحتاج هذه المعالجة SQL جديدًا إذا كان Hotfix 3 VERIFY قد نجح بالفعل.

## 2) بوابة الطالب

البوابة ليست واجهة فقط. التدفق الموجود هو:

- المعلم/الإدارة يفعّل PIN من ملف الطالب عبر `set_student_portal_pin`.
- `/portal` يرسل كود الطالب + PIN إلى Edge Function باسم `student-portal`.
- الدالة تستخدم service-role داخليًا فقط لاستدعاء `student_portal_authenticate`.
- المتصفح لا يقرأ جداول الاعتمادات أو الجلسات مباشرة.

Build 82 يضيف رسائل منفصلة لحالات: Function غير منشورة، أسرار Function ناقصة،
أو عقد SQL ناقص. كما ينسق كود الطالب/العائلة تلقائيًا إلى مجموعات من خمس خانات
مع `HAL-` أو `FAM-`، لذلك لا يحتاج الطالب إلى كتابة الشرطات.

### فحص SQL

شغّل أولًا:

`P1.27_BUILD82_HOTFIX7_VERIFY.sql`

إذا كانت فحوص البوابة فقط `false`، وبعد أخذ نسخة احتياطية، يمكن تشغيل:

`P1.27_BUILD82_HOTFIX7_PORTAL_REPAIR.sql`

الإصلاح المستهدف لا يعيد P7.3 ولا يستبدل scope helpers الحالية.

### نشر Edge Function

من مجلد `website` وبعد ربط Supabase CLI بالمشروع:

```bash
supabase secrets set PORTAL_RATE_LIMIT_PEPPER="RANDOM_LONG_SECRET"
supabase secrets set PORTAL_ALLOWED_ORIGINS="https://YOUR_WEB_DOMAIN"
supabase functions deploy student-portal --no-verify-jwt
```

بعد ذلك فعّل PIN جديدًا لطالب تجريبي من ملفه، ثم اختبر `/portal`.

## 3) Google Sign-In

الكود كان يستدعي Google OAuth بالفعل، لكن رسالة
`Unsupported provider: provider is not enabled` تعني أن Google Provider نفسه
غير مفعّل في إعدادات Auth للمشروع. Build 82 يعرض رسالة عربية عملية بدل JSON
الخام، ويعرض زر Google في الدخول وإنشاء الحساب معًا.

الإعداد المطلوب خارج الكود:

1. إنشاء OAuth Client من نوع Web في Google Auth Platform.
2. إضافة أصل الموقع ضمن Authorized JavaScript origins.
3. إضافة Supabase Callback URL الظاهر في صفحة Google Provider إلى Authorized redirect URIs.
4. إدخال Client ID وClient Secret وتفعيل Google في Supabase Authentication Providers.
5. إضافة رابط الموقع ورابط `/login?oauth=google` إلى Supabase URL Configuration / Redirect URLs.

## 4) P7.3 وربط/إنشاء المراكز

لا تعاود migration P7.3 التاريخية على قاعدة المالك الحالية. المشروع الحالي
يعتمد عقد Build 75/76 الذي يصلح P7.3 الجزئية ويضيف إنشاء المركز المباشر وفحص
الجاهزية. Build 82 يحسن الرسالة بحيث تميز نقص RPC/الصلاحية/العضوية وتعرض رمز
PostgREST آمنًا عند الخطأ غير المصنف، بدل رسالة «تعذر إتمام العملية» فقط.

شغّل `P1.27_BUILD82_HOTFIX7_VERIFY.sql`. إذا فشلت فحوص `supervision` فالمسار
الصحيح هو إصلاح Build 75/76 الحالي ثم إعادة VERIFY، وليس إعادة P7.3 القديمة.
