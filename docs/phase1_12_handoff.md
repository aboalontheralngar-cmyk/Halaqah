# تسليم P1.12 — جاهزية التشغيل والقبول الفعلي

التاريخ: 2026-07-22  
الإصدار: `4.2.0-alpha.8+50 (P1.12)`

## ما أُنجز

- لوحة جاهزية داخل الإعدادات تجمع سبعة فحوص تلقائية وخمسة اختبارات قبول فعلية.
- منع اعتبار النسخة جاهزة عند وجود مشكلة حرجة في البيانات أو نسخة حماية قديمة أو فشل اتصال أو غياب جلسة Supabase.
- إبقاء أخطاء النسخ التلقائي والحوادث وملاحظات البيانات ظاهرة كملاحظات تحتاج مراجعة.
- حفظ نتائج الاختبار اليدوي تحت مفتاح خاص برقم الإصدار حتى لا تنتقل موافقة نسخة قديمة إلى نسخة جديدة.
- تقرير جاهزية منقح قابل للنسخ والمشاركة.
- استعلام قراءة فقط يختبر الحالة الآمنة المقصودة لجداول البوابات.

## تفسير صورة السياسات

القيمة `false` في الاستعلام القديم تعني فقط أن عدد السياسات يساوي صفرًا. هذا ليس فشلًا وحده في جداول:

- `student_portal_credentials/sessions/login_attempts`
- `family_portal_credentials/sessions/login_attempts`

الحالة الصحيحة لها هي:

`RLS=true`, و`policies=0`, و`anon_direct=false`, و`authenticated_direct=false`.

## استعلام Supabase الصحيح

انسخ **محتوى** الملف التالي إلى SQL Editor:

`website/supabase/verification/20260722000100_p1_12_portal_security_readiness.sql`

الاستعلام للقراءة فقط ولا ينفذ `CREATE` أو `ALTER` أو `GRANT` أو `REVOKE` أو أي تعديل بيانات. يجب أن تكون نتيجة صفوف `portal-deny-all` وصف الملخص `passed=true`.

## المسار داخل التطبيق

`الإعدادات ← التشخيص ← فتح جاهزية التشغيل والإطلاق`

بعد معالجة العوائق، نفّذ بنود القبول الفعلية ثم فعّل كل بند نجح بالفعل.
