# P1.27 Build 84 Hotfix 9

## Goal

Build 84 turns synchronization from a full-domain polling loop into a delta-oriented protocol suitable for many independent centers, while finishing the OAuth/onboarding blockers and the requested memorization/revision/report features.

## Synchronization architecture

1. Flutter resolves the selected center/halaqa locally.
2. One authenticated `get_halaqah_sync_watermarks(center,halaqa)` RPC returns the latest server timestamp for each mutable domain plus `tombstone_max_id`.
3. The device compares those values with per-domain cloud cursors and combines them with SQLite `sync_dirty_stages`. A domain is skipped when neither side changed.
4. Cloud downloads execute inside `sync_remote_write_replay`, so imported rows do not schedule an echo upload.
5. The high-volume attendance/homework/memorization paths use updated-since local queries and updated-since cloud queries; exam questions are fetched/uploaded in batches instead of per template.
6. Server `updated_at` triggers are authoritative and indexes match the center/halaqa/update predicates.

The first bidirectional synchronization after applying Build 84 establishes cloud cursors and can still transfer existing rows. The meaningful performance test is the second no-change synchronization, then a third synchronization after changing only one domain.

## Google OAuth

The website is configured for Supabase PKCE. `/auth/callback` must be allow-listed in Supabase Auth Redirect URLs. The callback exchanges the code, writes the authenticated user into the app store, waits for the profile lookup, then routes existing users to `/select-center` and fresh users to `/onboarding`. Dashboard route guards explicitly treat OAuth return routes as public.

## Supervisory onboarding

`P1.27_BUILD84_HOTFIX9_APPLY.sql` recreates `create_supervisor_organization(text)` as an idempotent secured RPC, repairs/ensures the owner membership, and asks PostgREST to reload its schema cache. Do not replay historical P7.3 migrations.

## Connected revision range

The revision workspace keeps the existing checkbox/manual selection. A second route action opens a start/end picker. The generated range follows the student's memorization direction and rejects any ayah outside the recorded memorized segments.

## Excess reward tiers

The base completion reward remains proportional up to 100%. Once the student exceeds the target, the configured `extra_memorization` reward is multiplied by a tier: every 25% of excess adds one tier, capped at four. Historical automatic-point snapshots that predate Build 84 are recalculated with one tier to avoid rewriting past meaning.

## Printed report

Each day stores the actual memorization amount, target, and unit used for that date. Above-target days show `★` and the excess percentage. The header shows a circular indicator with remaining Quran percentage and remaining ayah count based on `student.totalMemorized` versus the Quran dataset.
