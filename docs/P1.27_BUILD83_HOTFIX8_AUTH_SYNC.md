# P1.27 Build 83 Hotfix 8 — OAuth + Notification Sync + Fast Upload

## Google OAuth

The website now uses Supabase PKCE with a dedicated `/auth/callback` route.
The public frontend origin is controlled by `NEXT_PUBLIC_APP_URL`, with runtime
protection against sending a production browser to a stale localhost origin.

Production still requires matching dashboard configuration:

- Supabase Auth Site URL = the published HTTPS frontend origin.
- Supabase Auth Redirect URLs includes `<origin>/auth/callback`.
- Google OAuth Authorized redirect URIs includes the Supabase Auth callback URL
  shown by the Google provider page.
- Google Auth Platform Branding contains the application identity.

A random Supabase project hostname remains visible on Google consent surfaces
until a Supabase custom or vanity domain is activated.

## Notifications 23514

The Flutter application emits these notification categories:

- `low_performance`
- `repeated_absence`
- `plan_completed`
- `dismissal_warning`
- `general`
- `surah_completed`
- `consecutive_no_recitation`
- `student_expelled`

Older cloud schemas only allowed the first five. Run
`P1.27_BUILD83_HOTFIX8_APPLY.sql`; the application also contains a temporary
legacy compatibility mapping so a stale CHECK constraint cannot block the
entire upload.

## Lightweight upload-only synchronization

SQLite schema 27 introduces `sync_dirty_stages` plus INSERT/UPDATE triggers for
synchronized local tables. Build 83 forces one full upload after upgrade, then
later **upload-only** runs skip clean domains and perform network work only for
domains changed locally. Dirty generations are acknowledged conditionally so a
local write made while an upload is running remains dirty for the next pass.

Delete synchronization remains handled by `sync_delete_outbox` and is not
removed by this optimization.
