# P1.24 Implementation Log — Learning Controls, RTL Reports, Courses

**Release:** `4.3.0-alpha.17+69 (P1.24)`  
**SQLite:** `23`  
**Supabase:** migration prepared only; manual execution required by project owner.

## Scope completed

1. **Restore the pre-P1.23 colors only.** The green/gold/warm-paper identity is restored in Flutter and web while the compact P1.23 spacing, typography hierarchy, flat cards, navigation heights, and interaction density remain.
2. **PDF system rebuild.** Every PDF document uses the application font `Readex Pro` through one shared `pw.ThemeData`; Tajawal/Helvetica fallbacks were removed to prevent mixed-font Arabic words. The font is declared as a raw Flutter asset for `rootBundle.load` as well as the application font family. Every exported page is RTL, and table builders explicitly reverse logical columns because PDF table column order is physical.
3. **PDF visual identity.** Shared headers, footers, report section titles, statistic blocks, tables, plans, receipts, exam results, Quran exam papers, student-period reports, halaqah reports, and QR cards use the restored application palette and lighter borders/surfaces.
4. **Behavior multi-reason assignment.** One or more point/violation reasons can be selected together, then assigned to one or many students. The cross-product is saved through one SQLite transaction so the operation is atomic.
5. **Behavior screen density.** Main student rows were redesigned as compact searchable rows with rank, name, warning state, point balance, and one action button instead of overloaded cards.
6. **Undo attendance.** Tapping an already selected present/late control clears attendance back to `unmarked` without forcing absent/excused. The undo touches only attendance/arrival/absence fields; memorization, revision, talaqqin, activity type, and recitation-exemption data already entered for that day are preserved.
7. **Independent learning units.** Each student now has a memorization unit and a separate review unit. Smart plans also store independent `unit` and `review_unit`. Supported units remain ayahs, lines, pages/faces, and hizbs.
8. **Talaqqin stage eligibility.** `talaqqin_enabled` is explicit per student. Only active, non-completed students with this flag appear in Talaqqin. The Talaqqin screen now includes an explicit «إنهاء مرحلة التلقين» action that turns the flag off after confirmation while preserving all historical Talaqqin sessions and memorization history.
9. **Exam management.** Oral and written exams can be printed and deleted. Deletion is synchronized through tombstones; if an exam gates a smart plan, the plan returns to pending test state instead of retaining a dangling exam id.
10. **Exams in student reports.** Student period/month reports now include exams in screen, WhatsApp text, and PDF with date/type/range/score/grade.
11. **RTL exam papers.** Quran exam templates and all PDF page families are explicitly RTL; logical table columns are converted to visual right-to-left order.
12. **Contextual Surah picker.** The shared Surah picker scrolls to the currently selected Surah. Direct memorization and Talaqqin initialize from the student's next memorization position, while exam creation/generation initializes from the student's current memorized frontier according to memorization direction. The index therefore opens around the student's working Surah instead of Al-Fatihah.
13. **Quran memorization/revision courses.** Added time-bounded courses with memorization/revision/mixed tracks, date range, study weekdays, independent daily memorization/review targets, status, notes, and multi-student enrollment. Active course targets feed the day's memorization/review workspace and automatic daily memorization points.
14. **Automatic point correction.** Partial target completion gives no positive automatic points. Exact completion gives only the configured completion reward. Actual work above the target gives the completion reward plus one configured extra reward. Hidden workload points are disabled. Page/face and hizb amounts are calculated from actual Quran line coverage instead of treating any touched page/hizb as complete. Quran entries whose source line metadata is zero use a conservative 0.5-line fallback so short final surahs do not collapse to zero progress.
15. **Temporary holds confirmed.** `full_pause` remains the operational hold for study/work/similar circumstances. It is distinct from absence, expulsion, and recitation-only pause.
16. **WhatsApp day details confirmed.** Student period reports include day name, date, attendance/activity/talaqqin/exemption details. The legacy monthly WhatsApp helper also includes day names and dates.
17. **Cloud/backups.** SQLite backup/restore includes Quran courses/enrollments. Supabase sync supports the new student/plan fields and course tables, with graceful local operation before the P1.24 migration is applied.
