# P1.27 Build 75 Hotfix 3 — share_plus / printing dependency resolution

**Date:** 2026-08-13  
**Scope:** Flutter Pub dependency resolution only  
**Database:** no SQL or SQLite change

## Owner acceptance already completed

The owner successfully ran `P1.27_BUILD75_VERIFY.sql` on the live Supabase project and every Build 75 check returned `passed = true`. No Build 75 SQL should be re-applied for this hotfix.

## Runtime evidence received

After installing Hotfix 2, `flutter pub get` failed before dependency download with this solver conflict:

- `share_plus 9.0.0` depends on `web ^0.5.0`.
- `printing >=5.13.2 <5.15.0` depends on `web ^1.0.0`.
- Build 75 Hotfix 2 pinned `printing 5.14.3` while leaving `share_plus 9.0.0`, so no common `web` version existed.

Because Pub resolution failed, `flutter analyze`, `flutter test`, and `flutter run` could not start.

## Root cause

Hotfix 2 fixed the old `printing 5.11.1` compile incompatibility but did not update the sharing plugin on the same `package:web` dependency generation. This was a dependency-pair compatibility error in the hotfix, not an application logic or Supabase failure.

## Fix

`pubspec.yaml` now pins:

```yaml
printing: 5.14.3
share_plus: 10.0.3
```

Why `share_plus 10.0.3`:

- it uses the `package:web 1.x` generation introduced in share_plus 10.0.1, so it can resolve with printing 5.14.3;
- it supports Flutter >=3.19.0 and Dart >=3.3.0, matching the project's declared Dart lower bound and the owner's current Flutter generation;
- it preserves the existing static APIs used throughout this project (`Share.share`, `Share.shareXFiles`, and `Share.shareUri`), so no sharing callsites need a risky API migration in this hotfix.

The project intentionally does **not** jump to share_plus 12/13 because those releases impose newer Android/Flutter toolchain requirements and/or larger breaking migrations that are unnecessary for this dependency conflict.
