# P1.27 Build 78 Hotfix 2

**Date:** 2026-08-16  
**Base:** Build 78 Hotfix 1  
**SQLite:** 26  
**Supabase SQL:** unchanged

## Root cause — plan printing

`SmartPlanScheduleService` intentionally emits a Friday catch-up row with
human-readable memorization/review instructions and an exact recitation range.
The PDF validator, however, required all three cells on every study day to
contain the word `سورة`. Because a catch-up Friday remains a study day, every
otherwise-valid plan spanning that Friday failed before PDF generation.

The validation is now isolated in `SmartPlanPrintPolicy`. A catch-up row
requires only exact recitation; ordinary full-plan days keep the original strict
memorization/review/recitation validation.
The plans screen also strips Dart's raw `Bad state:`/`Exception:` prefix before showing a print error.

## Root cause — long suspension sync

Hotfix 1 bounded each `set_study_suspension` call, but when the local
fingerprint was absent or changed the client could still replay all historical
suspensions sequentially. A poor connection multiplied the per-call delay.

Hotfix 2 fetches current remote suspensions once, computes a deterministic diff,
and sends only changed/deleted dates. The resulting remote state is reused for
the download half of a bidirectional sync, removing the second read.

## Concurrent sync protection

`SupabaseService` now has one active synchronization operation. Matching
requests join the active operation; a direction not covered by it waits until
the active operation finishes. This prevents foreground/manual sync and the
automatic coordinator from issuing competing mutation streams.

## Source-package prerequisite

The full-source archive supplied for review intentionally omits Tajawal `.ttf`
files but `pubspec.yaml` references them. They must be restored from the
existing project before Flutter build. This hotfix does not redistribute fonts.
