# P1.27 Build 79 — Installation Note

**Version:** `4.3.0-alpha.25+79`  
**Base:** Build 78  
**SQLite:** 26 — no migration  
**Supabase:** no new SQL  

## Install

1. Back up the current project and app data.
2. Apply the Build 79 modified-files package over Build 78.
3. Keep the working `pubspec.lock`; `flutter pub get` will remove only dependencies no longer referenced directly.
4. Do **not** re-run Build 78 SQL. Your Build 78 VERIFY result is already the required cloud state.

## Validate Flutter

```powershell
flutter clean
flutter pub get
flutter analyze
flutter test
flutter run
```

Do not continue to release packaging if analyze or tests fail.

## Build the optimized Android release

Set the same production Supabase values used by the application and run:

```powershell
$env:SUPABASE_URL="https://<project>.supabase.co"
$env:SUPABASE_PUBLISHABLE_KEY="<publishable-key>"
.\tools\build_lean_android.ps1
```

Outputs are copied to:

```text
build/release-artifacts/
```

including split APKs, `app-release.aab`, SHA-256 sums, and Android size reports.

Optional deep size analysis:

```powershell
$env:HALAQAH_ANALYZE_SIZE="true"
.\tools\build_lean_android.ps1
```

## First size baseline

After one production release is functionally accepted, copy:

```text
build/release-artifacts/android-size-baseline-candidate.json
```

to:

```text
tools/android_size_baseline.json
```

Only then enable CI growth enforcement. This prevents an arbitrary unmeasured size target from blocking valid releases.

## Full-source font note

The full-source upgrade intentionally does not redistribute the Tajawal binary font files. Prefer the modified-files-only package over your existing project so the working font files stay in place.
